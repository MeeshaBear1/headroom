# Pre-registration — headroom calibration gate

**Status: FROZEN.** Written and committed before any trial of any arm ran.
Everything below is fixed. A change to any frozen field after trial 1 invalidates
every affected trial and the invalidation is recorded here, not absorbed.

Date frozen: 2026-07-24
Purpose: decide which of the three shipped probes has room to show uplift at
Opus 5 and Sonnet 5 tier, **before** spending on any contrast.

## Why a separate freeze for the gate

The gate is arm A only. It touches no library, so nothing about arm B needs to be
frozen yet — and it must not be, because the gate's own output selects the primary
probe for the contrast. Freezing the contrast now would mean choosing the primary
probe with no information, and freezing it *after* seeing arm B data would be
p-hacking. Gate first, freeze the contrast second, look at B third.

## n

**n = 10 per probe per model.** 3 probes × 2 models × 10 = **60 trials.**

n = 10 is chosen because the gate is a screen, not a test: it needs to separate
"already at ceiling" from "room to move", and 10 trials resolve a ≥90% threshold
sharply (9 or 10 passes). It is explicitly **not** powered to detect an effect —
see the sample-size table in `skills/uplift-statistics`, and note that a null at
n = 10 is not a null.

## Gate thresholds (frozen)

Applied per probe, per model, on arm A pass rate:

| Arm A pass rate | Verdict | Consequence |
|---|---|---|
| ≥ 90% (9/10 or 10/10) | **VOID-FOR-TIER** | no contrast is bought for that probe at that tier; the void is published |
| 5% – 90% (1/10 – 8/10) | **HAS-HEADROOM** | eligible to be the contrast's primary probe |
| ≤ 5% (0/10) | **FLOOR-SUSPECT** | not eligible as primary until the task is shown achievable at all |

## Primary-probe selection rule (frozen, applied to gate data only)

For each subject model independently:

1. Discard probes marked VOID-FOR-TIER or FLOOR-SUSPECT.
2. Discard `overcaution` from consideration — it is a harm control, never a primary.
3. Among the remainder, the **primary** is the probe with the **lowest arm-A pass
   rate**. Ties break alphabetically by probe id.
4. `overcaution` is run at the same n as its matched probe `disclosure` whenever
   `disclosure` is run in the contrast, regardless of `overcaution`'s own gate
   verdict. A harm control is not selected on its promise.
5. If no probe survives step 1 for a model, the verdict for that model is
   **VOID-FOR-TIER across the shipped probe set**, no contrast is run, and that is
   the published result.

## Resolving FLOOR-SUSPECT

If a probe returns 0/10, before it is read as "the model needs help":

1. Re-run its offline selftest — the oracle must still pass the pristine-state gate.
2. Run one arm-A trial with the ground truth handed over verbatim in the prompt.
   If that fails too, the probe is broken, not the model, and the probe is dropped
   with the reason recorded.

## Abort rules

- More than 6 `infra-*` rows in a single gate invocation → the run halts, the
  harness is fixed, and the affected trials are re-run from scratch. Infra rows are
  never counted as behavioural failures.
- The runner writes a `STOP` file the driver checks each iteration, so an operator
  halt does not corrupt a trial mid-flight.
- Any trial that does not reach the statistics is named in the run record with its
  reason. No silent caps.

## Exclusions declared in advance

- `infra-*` rows: excluded from all rates, counted and reported separately.
- Nothing else. In particular, no row is excluded for looking anomalous.

## Arm C availability at freeze time

Arm C (a stronger ceiling model, unaided) is not part of this phase. For the
record: `claude-fable-5` was unavailable to the operator at freeze time, so if the
contrast phase needs a ceiling arm above `claude-opus-5`, that arm is deferred and
must be disclosed as deferred rather than quietly dropped. For a `claude-sonnet-5`
subject, arm C is `claude-opus-5` unaided.

## What gets published

All 60 rows and all six per-probe-per-model verdicts, whatever they are —
including the case where every probe is void at both tiers, which would mean this
repository's shipped probes measure nothing at frontier tier. That outcome is
recorded as the result, not as a reason to go and build easier probes.
